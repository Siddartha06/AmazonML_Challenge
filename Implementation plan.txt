STEP 2 — Build a proper validation strategy

This step is extremely important because we need to optimize the actual competition metric, not generic accuracy.

Now implement a leakage-safe validation framework.

Competition metric:
F0.5 = (1.25 * Precision * Recall) / (0.25 * Precision + Recall)

The competition calculates F0.5 per Source-1 entity and then macro-averages across Source-1 entities.

Singleton behavior is important:
- correctly predicting no matches for a singleton gets 1.0
- incorrectly predicting any match gets 0.0

Requirements:

1. Split the training Source-1 entities into train and validation groups.
2. The split must happen at the Source-1 entity level.
3. Never split individual candidate pairs independently.
4. Ensure all records associated with a validation Source-1 entity are excluded from training.
5. Make the split reproducible with a fixed random seed.
6. Prefer stratification based on match-count groups if practical:
   - 0 matches
   - 1 match
   - 2 matches
   - 3+ matches

Implement:

src/validation.py

Functions should include:

create_entity_level_split(...)
load_ground_truth(...)
calculate_entity_f05(...)
evaluate_predictions(...)
evaluate_thresholds(...)

The evaluator must correctly handle:
- empty predictions
- multiple matches
- duplicate predictions
- singleton Source-1 entities
- macro averaging over Source-1 entities

Create:
reports/02_validation.md

Include tests proving the evaluator works on small manually constructed examples.

Do NOT train any ML model yet.

Run the evaluator tests and report the results.
